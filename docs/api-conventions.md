# API conventions

Applies to every endpoint of the Laravel API. Error responses: [error-handling.md](error-handling.md).

## URLs

- Base: `{API_URL}/api/v1`. Breaking changes require `/api/v2`. Additive changes (new fields, new
  endpoints) stay in v1, so clients must ignore unknown fields.
- Resources are plural, kebab-case nouns: `/api/v1/products`, `/api/v1/purchase-orders/{id}`.
- Nest at most one level, and only for true ownership: `/api/v1/purchase-orders/{id}/items`.
- State transitions are sub-resource actions with `POST`: `/api/v1/sales/{id}/void`,
  `/api/v1/shifts/{id}/close`.
- Route names: `api.v1.<resource>.<action>`.

| Method | Use | Success status |
| ------ | --- | -------------- |
| `GET` | Read | 200 |
| `POST` | Create / perform action | 201 (created) or 200 (action) |
| `PUT` | Full replace | 200 |
| `PATCH` | Partial update | 200 |
| `DELETE` | Delete / deactivate | 204 (no body) |

## Request headers

| Header | Who sends it | Purpose |
| ------ | ------------ | ------- |
| `Accept: application/json` | All clients | Always JSON responses |
| `X-Request-Id` | All clients (UUIDv7) | Correlates client and server logs; echoed back. Generated by the server when missing |
| `Authorization: Bearer <token>` | Terminals | Sanctum device token |
| `X-XSRF-TOKEN` + session cookie | Web app | Sanctum cookie authentication (axios sets it from the `XSRF-TOKEN` cookie) |
| `X-Compriva-Device` | Terminals | Install ID of the terminal |
| `Idempotency-Key` | Clients, for retryable writes | The server applies a given key once and replays the first result for repeats |

## Response bodies

Success, single resource or action result:

```json
{ "data": { "id": 12, "name": "Rice 5kg", "price": 32500 } }
```

Success, list (paginated):

```json
{
  "data": [ { "id": 12, "name": "Rice 5kg" } ],
  "meta": { "current_page": 1, "per_page": 25, "total": 120, "last_page": 5, "from": 1, "to": 25 }
}
```

Error: `{ "error": { "code", "message", "details", "request_id" } }`. See [error-handling.md](error-handling.md).

Rules:

- Always build responses with **API Resources** (`app/Http/Resources/V1/...`), never by
  returning models directly. That way hidden columns can't leak and the shape stays stable.
- Successful bodies are always wrapped in `data`. `204` responses have no body.

## Data types

| Kind | Format | Example |
| ---- | ------ | ------- |
| Field names | snake_case | `unit_price`, `created_at` |
| IDs | UUIDv7 string (every resource) | `"019a2f4c-7b1e-7c3a-9f00-3c2d1e0a5b6c"` |
| Money | **Decimal string, 4 places**, exactly as stored (`DECIMAL(15,4)`). Never a JSON number | `"325.0000"` = ₱325.00 |
| Quantity | Decimal string, 4 places, in the stated unit | `"1.2500"` |
| Unit conversion factor | Decimal string, 6 places | `"12.000000"` |
| Tax rate | Percentage, decimal string, 4 places | `"12.0000"` (VAT 12%) |
| Timestamp | ISO-8601 UTC with `Z` | `"2026-10-30T04:12:00Z"` |
| Business date | `YYYY-MM-DD` in Asia/Manila | `"2026-10-30"` |
| Enum | lowercase snake_case string | `"gcash"`, `"partially_received"` |
| Boolean | JSON boolean | `true` |
| Absent value | `null` (keys are always present) | `"barcode": null` |

## Lists: pagination, filtering, sorting, search

- `?page=2&per_page=50`: default 25, maximum 100.
- `?filter[status]=active&filter[category_id]=3`: exact-match filters, whitelisted per endpoint.
- `?sort=name` ascending, `?sort=-created_at` descending, comma-separated for several.
- `?q=rice`: free-text search, where supported.
- Terminals do **not** page through master data. They use the sync endpoints
  ([offline-sync.md](offline-sync.md)).

## Idempotency

- Every write a terminal sends is retryable and **must** be idempotent:
  - Sync operations carry an `operation_id` (UUIDv7) in the body, and that is the idempotency key.
  - Other retryable POSTs send `Idempotency-Key: <uuidv7>`.
- The server stores `(device, key) → response` and replays the stored response for duplicates.
  A duplicate with a *different* payload is rejected with `409 CONFLICT`.
- The web app sends `Idempotency-Key` on create forms, so double-submits are harmless.

## Authentication and authorization

Full endpoint list, flows and rules: [authentication.md](authentication.md). In short:

- Every non-public route has `auth:sanctum` plus an actor check: `actor.user` (an active person)
  or `actor.device` (an active, paired terminal). Permissions are enforced with `can:<permission>`.
- `GET /sanctum/csrf-cookie` (outside `/api/v1`) precedes web sign-in.

## Public endpoints

| Endpoint | Purpose |
| -------- | ------- |
| `GET /api/v1/health` | Connectivity probe: `status`, `api_version`, `server_time` (used for clock-skew checks), `timezone`, `currency`, `checks.database`. Returns 503 when the database is down |
| `POST /api/v1/auth/login` | Web sign-in (session cookie; web app origin only) |
| `POST /api/v1/terminal/pair` | Terminal pairing with a one-time code |
| `GET /up` | Laravel's process health check, for load balancers |

## Rate limits

| Limiter | Limit | Applies to |
| ------- | ----- | ---------- |
| `api` | 300 / minute per user, device or IP | Every `/api` route |
| `login` | 5 / minute per username + IP, and 20 / minute per IP | `POST /auth/login` |
| `terminal-login` | 5 / minute per terminal + username, and 20 / minute per terminal | `POST /terminal/login` |
| `pairing` | 5 / minute per IP | `POST /terminal/pair` |
| Sync push | Batches of at most `COMPRIVA_SYNC_MAX_BATCH_SIZE` (100) operations | Sync phase |

Exceeding a limit returns `429 TOO_MANY_REQUESTS` with a `Retry-After` header.
